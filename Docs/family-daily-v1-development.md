# Family Daily V1 — 第一阶段开发说明

> 日期：2026-08-22  
> 状态：网页端 PoC 优先验证；Android 原型暂缓迭代

## 当前开发焦点

先完成网页端 PoC，并通过真实家庭使用验证“提问 → 语音回答 → AI 整理 → 确认分享 → 家人回复”闭环。Android 客户端保留现有原型，在网页端 PoC 跑通后再统一修改，避免两个客户端同时迭代造成重复工作。

## 本阶段目标

实现产品文档中最小闭环的第一个可运行版本：

```text
创建问题
→ 父母录制回答
→ 后端保存原始录音
→ Gemini 返回转写和保守摘要
→ 用户确认分享
→ 家人查看并回复
```

本阶段不实现正式账号、邀请链接、Push、Family Daily、人物识别或自动 Thread。

## 技术切片

### 后端

- Go HTTP 服务；
- SQLite 持久化问题、回答和回复；
- 文件系统保存原始录音；
- 所有状态变化写入追加式本地审计历史；
- 录音先在本地持久化，再调用 Gemini；
- 重新录制会归档旧版本，不会直接物理删除；
- 生产环境验证专用盘标记，盘未挂载时拒绝启动；
- 家庭令牌保护 API 和媒体访问；
- Gemini Interactions API 处理短音频；
- Gemini 请求使用 `store=false`，不依赖服务端对话记忆；
- AI 失败时保留原始录音并显示明确状态；
- 分享前允许删除草稿并重新录制。

### Android

- 单屏原生 Android App；
- 创建一个具体问题；
- 大按钮录音；
- 上传 MPEG-4/AAC 语音；
- 查看 AI 摘要和播放原声；
- 确认分享或重新录制；
- 查看家庭动态并回复。

### 本地身份假设

为了尽快验证闭环，V1 使用固定演示身份：

- 家庭：`our-family`；
- 提问人：`洋宇`；
- 回答人：`爸爸`。

这些值只属于本地原型。正式家庭试用前，需要替换为用户、家庭成员和邀请关系。

## 已完成的验证

### 自动化验证

后端测试覆盖：

- 未携带家庭令牌时拒绝访问；
- 创建问题；
- 上传并保存录音；
- 生成转写和摘要；
- 确认分享；
- 家人回复；
- 删除未分享草稿后重新录制。

Android Debug APK 已成功构建。

### 真实 Gemini 验证

使用一段无个人信息的中文测试语音完成真实 API 调用。结果包括：

- 正确识别“老张去医院检查、没有大问题、一起下棋、赢了两盘”；
- 成功生成一段简短摘要；
- AI 处理耗时约 3.5 秒；
- 随后成功完成分享和回复。

这证明后端到 Gemini 的真实音频链路可用，但还不能证明方言、嘈杂环境和不同老人语速下的准确性。

## 下一学习边界

下一步不是增加更多功能，而是在 Android 模拟器或真机上完成一次真实录音：

1. 手机创建问题；
2. 手机录制 MPEG-4/AAC；
3. 后端和 Gemini 正确处理手机录音；
4. 手机上显示摘要并播放原声；
5. 确认分享并回复。

完成后应立即找 2–3 个内部家庭体验，重点观察：

- 老人是否理解录音按钮状态；
- 首次麦克风授权是否造成流失；
- 录完以后等待 3–5 秒是否可接受；
- AI 摘要是否改变原意；
- 家人的回复是否构成真实价值时刻。

## 进入家庭试用前必须补齐

- 正式用户身份和家庭邀请；
- 不再使用固定本地家庭令牌；
- HTTPS；
- 可配置的家庭成员姓名；
- 回答和录音的完整删除入口；
- 专用盘之外的加密备份与恢复演练；
- 对 AI 数据处理的清晰提示和同意；
- Android 真机上的完整闭环证据。
