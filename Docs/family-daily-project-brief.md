# Family Daily — 项目简介

> 版本：2026-08-22  
> 阶段：首个真实家庭试验  
> 一句话介绍：Family Daily 从一个具体问题开始，让父母用声音自然回答，由 AI 谨慎整理、本人确认后再分享，让异地家人更容易把一次关心继续聊下去。

## 1. 为什么做这个项目

很多成年子女想更了解父母最近的生活，却经常遇到三个现实问题：

- 想联系，但一时不知道问什么；
- 电话要求双方同时有空，群聊里的话题又很快被新消息淹没；
- 父母更习惯说话而不是打字，很多有温度的生活细节没有被留下来。

Family Daily 不试图增加一种新的社交负担。它把一次联系缩短为一个很小的动作：子女问一个具体问题，父母按下大按钮说一段话，家人听见原声、读到整理后的重点，再自然地回复。

## 2. 产品定位

Family Daily 是一个私密、本地优先的家庭交流与记忆空间。

它不是家庭群聊的替代品，也不是让 AI 自动替家人写日记。它补足群聊和电话之间缺少的一层：

> 不要求所有人同时在线，也不让有价值的回答消失在消息流里。

长期愿景是：

> **Speak → Share → Remember → Reconnect**  
> 说出来 → 分享它 → 记下来 → 再靠近一点

当前 MVP 只验证最短价值路径：

> **Ask → Speak → Confirm → Reply**  
> 问一问 → 说一说 → 确认分享 → 聊下去

## 3. 目标用户

### 核心用户

一名与父母异地居住、愿意主动维系联系的成年子女。

### 参与用户

愿意回答家人的问题，但不愿学习复杂操作、也不喜欢长篇打字的父母或长辈。

### 用户任务

子女能轻松发出一个具体问题；父母能直接用语音回答；其他家人看到后能自然回应或继续提问。

## 4. MVP Card

**Target user**  
异地生活的成年子女，以及更习惯语音表达的父母。

**User job / problem**  
低压力地了解家人的真实近况，并让一次关心产生后续交流。

**Riskiest assumption**  
保留原声、同时提供 AI 整理内容，是否真的会降低家人的阅读和表达门槛，并提高回复意愿。

**P1 end-to-end loop**

```text
子女发送一个具体问题
→ 父母打开问题并录制语音
→ 原始录音先保存到家庭服务器
→ AI 转写并生成保守摘要
→ 父母试听、确认或重新录制
→ 确认后的内容进入家庭动态
→ 至少一名家人回复或继续提问
```

**Success proof**  
真实家庭完成整个闭环，并在父母分享后产生至少一次有意义的家人回复。AI 成功生成摘要、测试通过或页面被打开，都不能单独算作产品成功。

**No-gos**

- 不把 Family Daily 做成公开社交网络；
- 不让 AI 代替家人表达关心或自动发布；
- 不做健康诊断、风险判断或紧急通知；
- 不在验证前扩展知识图谱、复杂推荐、分布式存储或自动化平台；
- 不把家庭权威数据迁移到托管数据库或对象存储。

**Appetite / time box**  
先用 2–3 个内部家庭完成可用性试验，再扩展到 10–20 个家庭、持续 2–3 周。到达学习边界后停止加功能，先判断闭环是否真正创造价值。

## 5. 核心体验

一个典型场景是：

1. 洋宇问爸爸：“爸，你上次说老张膝盖不舒服，他后来去看了吗？”
2. 爸爸按下大录音按钮，像平时聊天一样回答。
3. Family Daily 保留原声，并生成转写和一段明确标记为“AI 整理”的简短摘要。
4. 爸爸试听后确认分享；如果不满意，可以重新录制，旧草稿会归档留痕。
5. 洋宇听完回复：“那就好。你们最近下棋谁赢得多？”

最后一步才是价值时刻：系统没有只“保存一段音频”，而是帮助家人开始了下一轮交流。

## 6. P1 产品范围

### 必须有

- 家庭成员使用自己的身份进入家庭空间；
- 子女向指定家人提出一个不超过 300 字的具体问题；
- 父母通过清楚的大按钮录制、停止和试听；
- 原始录音在 AI 处理前先安全保存；
- AI 提供转写和简短、忠于原意的摘要；
- 回答者可以确认分享、取消或重新录制；
- 家人可以播放原声、阅读 AI 整理并回复；
- 家庭内容只对有权访问的成员开放；
- AI 失败时保留原始录音，并给出明确的可恢复状态。

### Later

- 自动话题追踪和长期人物关系；
- 原生 Push Notification；
- 完整离线体验和应用商店发布；
- 跨家庭发现或公开分享；
- 大规模并发、队列、同步和多副本存储；
- 由 AI 自动决定哪些家庭内容应该分享。

## 7. 隐私与数据原则

Family Daily 面向的是不应该成为平台内容的家庭记忆，因此产品边界本身就是功能的一部分：

- SQLite、原始录音、转写、摘要、版本和审计事件保存在家庭自己的本地服务器；
- Gemini 只对单次请求做无状态处理，权威记录仍然留在本地；
- 每位成员拥有隔离的 Space，成员凭证不能读取另一位成员的私密文件；
- “仅自己”和“家庭可见”是用户决定，不由 AI 替用户做最终选择；
- 重新录制会归档旧草稿以便追溯；未来的永久删除必须同时删除相关版本和媒体；
- 生产环境在专用存储盘没有正确挂载时拒绝启动，避免家庭数据误写到系统盘。

## 8. 当前产品与技术状态

### 已存在的基础

- Go + SQLite 本地后端，以及本地媒体和审计历史；
- 成员级登录、管理员边界和成员隔离的 Space；
- 问题、语音回答、AI 转写与摘要、确认分享、回复和草稿历史的后端能力；
- React 家庭动态、个人 Space、老人模式、图片/视频分享和 Family Daily 摘要；
- Android 原型及本地照片增量同步能力；
- 前端由 GitHub Pages 提供，后端运行在家庭 Mac mini，并通过独立 API 域名访问。

### 当前最重要的产品缺口

问答闭环的后端已经存在，但 React UI 还没有完整呈现“提问 → 语音回答 → 确认 → 回复”。因此当前优先事项不是继续增加旁支能力，而是把这条 P1 链路接进用户真正操作的页面，并用一组真实家庭数据完成演示。

## 9. 最小技术切片

| 用户步骤 | 最小产品路径 | 可观察证据 |
| --- | --- | --- |
| 子女提问 | 复用成员身份与问题 API，新增提问入口 | 指定回答者能看到待回答问题 |
| 父母回答 | 老人模式复用录制交互，只上传音频回答 | 本地保存原声，页面显示处理中 |
| AI 整理 | 复用现有 Gemini 音频处理 | 显示转写和“AI 整理”，不添加原音频之外的事实 |
| 本人确认 | 接入分享、归档与重录状态 | 未确认内容不进入家庭动态 |
| 家人回应 | 回答详情页接入回复 API | 分享后出现一条真实成员回复 |

## 10. 试验与成功指标

首轮试验重点观察行为，而不是功能数量：

- 被打开的问题中，有多少完成了语音回答；
- 父母是否能独立理解录音、等待、确认和重录；
- AI 摘要是否被认为忠于原意；
- 分享后的回答中，有多少在 24 小时内收到家人回复；
- 一次回复是否进一步产生后续问题或线下联系。

建议的第一阶段成功门槛：至少 2–3 个真实家庭各完成一次闭环，其中大多数回答无需旁人指导完成录制与确认，并且超过一半的已分享回答收到有内容的回复。

## 11. 项目承诺

Family Daily 的目标不是替家人记住一切，而是让一个原本可能没有发生的交流，更容易开始、更值得留下，也更容易继续。
